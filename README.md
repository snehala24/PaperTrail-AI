# PaperTrail AI 📑🔬

> **Multi-Paper Research Evidence Workspace**  
> Differentiator: A claim-to-evidence ledger across multiple papers, apparent-conflict handling, and a two-step citation validator (existence, then support), backed by an empirical benchmark.

---

## 💡 Overview

PaperTrail AI is **not** a generic "chat with PDFs" wrapper. It is built for researchers who require grounded, verifiable synthesis across multiple academic papers with rigorous evidence tracking.

### Core Differentiators
1. **Claim-to-Evidence Ledger**: Every sentence generated by the system maps directly to atomic claims linked to exact chunk IDs in source documents.
2. **Apparent-Conflict Handling**: When papers disagree, claims are flagged as *apparent conflicts* annotated with causal reasons (different datasets, metrics, sample sizes, or test conditions)—never asserting definitive contradictions without context.
3. **Two-Step Citation Validator**: Validates citations in two distinct phases:
   - **Step 1 (Existence)**: Confirms the chunk ID exists in the corpus and retrieved context.
   - **Step 2 (Support)**: Evaluates whether the cited chunk semantically supports, weakens, contextualizes, or is insufficient for the claim.
4. **Honest Abstention**: When retrieved evidence is insufficient or contradictory without resolution, the system explicitly abstains rather than hallucinating.
5. **Empirical Evaluation**: Validated against an annotated benchmark measuring retrieval metrics (Recall@k, MRR, nDCG), grounding fidelity (citation precision/coverage, claim support rate), and conflict accuracy.

## 📐 Architecture Pipeline

```text
[PDF Upload]
     │
     ▼
[Parser (PyMuPDF)] ──(page/section aware, extraction failure recording)
     │
     ▼
[Chunker]
     │
     ▼
[Hybrid Retrieval Index]
  ├── Dense Index (FAISS CPU + sentence-transformers MiniLM)
  └── Lexical Index (BM25)
     │
     ▼
[Score Fusion (RRF / Weighted)]
     │
     ▼
[Cross-Encoder Reranker]
     │
     ▼
[Grounded LLM Answer Generation] ──(Retrieval-only context)
     │
     ▼
[Atomic Claim Extraction]
     │
     ▼
[Evidence Linking & Conflict Detection] ──(supports | weakens | contradicts | contextualizes | insufficient)
     │
     ▼
[Two-Step Citation Validation]
  ├── Phase 1: Existence Check
  └── Phase 2: Support Verification
     │
     ▼
[Validated Answer or Abstention Ledger]
```

## 🛠️ Tech Stack

- **Backend**: Python 3.11+, FastAPI, Pydantic v2, PyMuPDF (fitz), sentence-transformers (MiniLM class), rank-bm25, FAISS (CPU), pytest.
- **LLM**: Gemini via an abstract `LLMProvider` interface (model dynamically resolved from `GEMINI_MODEL`).
- **Frontend**: Next.js, TypeScript, Tailwind CSS.
- **Evaluation**: Custom offline eval harness logging to `eval/runs/`.

## 🚀 Getting Started

### 1. Prerequisites
- Python 3.11+
- Node.js 18+ (for frontend)
- Google Gemini API key

### 2. Backend Setup
```bash
# Clone the repository
git clone <repo-url>
cd "papertrail Ai"

# Create and activate virtual environment
python -m venv .venv
# On Windows:
.venv\Scripts\activate
# On Linux/macOS:
source .venv/bin/activate

# Install dependencies
pip install -r backend/requirements.txt

# Configure environment
cp .env.example .env
# Edit .env and supply GEMINI_API_KEY
```

### 3. Running Backend Tests
```bash
pytest backend/tests -v
```

### 4. Running Backend Server
```bash
uvicorn backend.app.main:app --reload --host 0.0.0.0 --port 8000
```
API Documentation will be available at `http://localhost:8000/docs`.

## 📊 Evaluation Protocols

Evaluations are never based on subjective impressions. Metrics are recorded in `eval/runs/` with full provenance (commit hash, model version, retrieval parameters):
- **Retrieval**: Recall@k, Precision@k, MRR, nDCG (segmented by question type).
- **Grounding**: Citation precision, citation coverage, claim support rate, unsupported-claim rate.
- **Conflict**: Precision, recall, false-conflict rate on opposing claims.
- **Abstention**: Accuracy and reliability on unanswerable queries.

## 📜 Development Rules
1. **Contracts First**: All schemas must be defined and tested before implementations.
2. **Transparent Grounding**: Unsupported claims are explicitly flagged, never silently dropped.
3. **Apparent Conflicts**: Contradictions are documented with reasons (dataset, metric, test setup).
4. **No Premature Complexity**: No Redis, Celery, or Postgres until MVP validation is complete.
